# Ginkgo 美食地图功能说明

## 这是什么系统

Ginkgo 美食地图是一个面向电子科技大学学生的校园美食平台。系统最终会帮助学生查找校园及周边餐厅、查看他人的真实评价，并分享自己的用餐体验。

当前项目仍处于重构开发阶段。下面将“已经可以使用”和“还在开发”的功能分开列出，避免把计划中的功能误认为已经完成。

注册、登录、自动保留登录和找回密码已合并发布，用户已确认基础验收通过。其他美食业务仍处于后续重构阶段，不能将计划中的功能当成已经可用。

餐厅目录、详情和杯型评分说明保留原版视觉与手机布局，餐厅真实接口及新增/编辑/删除已接入。本地另有明确标记的25家联调模拟店铺；线上能力以实际部署版本为准，模拟资料不代表经营信息已核实。

## 当前已经可以使用

### 浏览餐厅目录与详情（本地真实接口）

首页已改为美食发现与目录页面。用户可以搜索店名、地址、分类或标签，按分类、杯型组合筛选，选择只看推荐或踩雷，按评分维度、评价数、人均或距校区直线距离排序，并分页查看结果。

本轮恢复原版兔子举“辣鸡！”牌子的封面、页头杯子、杯型徽章和“电子科技大学 Ginkgo 烹饪社 · 成都觅食指南……”介绍，保留“不好吃，就举牌子。”原标语。首页缩短封面区，让手机用户更早看到店铺；搜索常驻，分类及推荐/踩雷等条件在“更多筛选”中展开，收起后显示已选项数且继续生效。杯型可横向滑动选择，重置可清除条件。翻页后回到结果栏，从详情使用浏览器后退时恢复原页码、筛选及阅读位置。

点击店铺可打开独立详情链接，查看名称、地址、标签、距清水河校区距离及复制/分享入口；链接可直接打开和刷新，不存在的店铺会给出返回入口。剪贴板不可用时提供手动复制文本。

- 目录、分类和详情从后端读取；搜索、筛选、排序、计数和分页由服务端统一执行，不在当前页二次筛选。加载中会提示，网络失败可重试，空库或无匹配结果会显示空态，不再用预览快照补齐。
- 本地按用户要求手动写入25家原版候选，统一显示“联调模拟”标签，仅供测试；没有示例评价或评分，全部待评级，评分和推荐率显示“—”。无评级店铺不算推荐或踩雷。
- 模拟人均是旧档位估值，经营状态与地址未经核实；旧坐标未确认，显示“位置待补”，不伪造距离。未建立历史账号归属。
- 公开浏览不受旧登录凭证过期影响；登录后的管理操作仍校验身份和权限。餐厅维护表单已接入，在线地图、评价发布和图片尚未接入。
- 首页不再向普通用户展示数据库、后端框架等工程说明，基础状态接口仍保留用于开发和部署检查。

### 新增、编辑和删除餐厅（本地真实接口）

从餐厅目录右上角点击“新增餐厅”。未登录会提示登录，成功后返回新增页；已登录可填写名称、分类、人均、地址、标签和经营状态。人均可选未知、填报具体金额或估值，快捷档位只辅助填入估值，可继续调整。名称最多40字、地址80字，人均1–5000整数元；标签每行一个，最多8个、输入总共80字。

新增和编辑都需要核对并确认位置。当前先支持手动填写GCJ-02经纬度，最多6位小数，不自动填校园坐标；地图搜索和点选尚未接入。修改经纬度后需要再次确认。

餐厅详情会向服务端确认当前账号的管理权限，只有创建者或管理员能看到“编辑餐厅”和“删除餐厅”。普通用户不能编辑别人的店，也不能认领25家未知归属的联调模拟店。直接打开无权限的编辑链接也会被拒绝；管理员可以纠错，但不会改变原创建者和来源。

编辑会填入原有完整资料，保存替换整份资料及标签，清空地址/标签会一并清空。最后成功保存的完整内容生效，旧页面保存仍可能覆盖其他人的修改。停业只是经营状态，餐厅仍可阅读。

删除前显示餐厅名称、当前评价数量及影响，需要再次确认；取消不会删除。删除成功后返回目录，列表、搜索和公开详情均隐藏该店。标签与历史资料保留，仅管理员可恢复；管理员回收站页面仍待开发。

保存或删除失败会显示原因，保存失败保留输入，不提前显示成功；提交期间禁止重复操作。超时结果不确定时提示先核对目录或详情，不自动重发新增。离开未保存页面会提醒；退出或跨标签页切换账号后锁住原草稿，需要重新打开页面，避免以另一个账号提交。草稿只保留在当前页面内，不额外持久保存。

### 查看杯型评分说明

用户可从导航、首页或餐厅详情进入评分说明，查看味道、性价比、服务和环境四个维度、五档杯型与待评级的区别，以及综合分、推荐率的计算规则。说明特别区分展示舍入与实际判档：原始综合分8.55即使显示为8.6，仍属于超大杯。

杯型沿用原版颜色与标语：全家桶“神店，冲”、超大杯“强推”、大杯“值得一去”、中杯“中规中矩”、小杯“踩雷预警”，待评级“等你来评”。评分说明页保留原版封面与社团内部测评、不接推广的说明。

### 获取注册邮箱验证码

用户可以申请注册验证码，但邮箱必须属于系统允许的电子科技大学学生邮箱域名。当前默认只允许以 `@std.uestc.edu.cn` 结尾的邮箱，并且会精确检查域名，不能用相似域名冒充。

为了防止验证码被滥用：

- 验证码是 6 位数字，5 分钟后失效。
- 同一个邮箱 60 秒内不能重复发送。
- 同一个邮箱在一小时和一天内都有发送次数上限。
- 连续输错次数达到上限后，当前验证码会失效。
- 验证码成功使用后立即失效，不能再次使用。
- 系统只保存验证码的校验结果，不直接保存用户收到的明文验证码。

如果邮箱已经注册，系统不会再次发送注册验证码。

### 使用校园邮箱注册账号

用户可以提交校园邮箱、收到的验证码、用户名和密码创建账号。系统会再次检查邮箱、验证码、用户名和密码，不能只靠前端页面的提示绕过规则。

目前注册后端接口和前端注册页面都已经完成。用户可以从首页或顶部导航进入注册页，填写学生邮箱并发送验证码，然后填写验证码、用户名、密码和确认密码完成注册。页面会提示输入问题、接口错误和注册结果，并在验证码发送成功后显示60秒重新发送倒计时。

- 邮箱必须属于允许的校园邮箱域名，当前默认为 `@std.uestc.edu.cn`。
- 用户名必须是 3 至 32 个文字、数字或下划线，并且不能与现有用户重复。
- 密码至少 8 个字符，并且至少包含字母或中文等文字以及数字。
- 密码不会以原文保存，数据库中只保存无法直接还原的安全哈希。
- 每个邮箱和用户名只能注册一个账号，即使多人同时提交也会由数据库阻止重复数据。
- 注册验证码只能成功使用一次，注册验证码不能用于密码重置。

注册成功后系统不会自动登录，也不会直接返回登录凭证。用户可以点击成功提示中的“前往登录”，使用用户名和密码登录。

本地联调所需的账号存储空间已初始化，可以开始从注册页面测试创建账号。系统不会预先创建用户或管理员账号。

### 通过校园邮箱找回密码

已经注册的用户可以通过绑定的校园邮箱申请密码重置验证码。为了避免别人利用接口查询某个邮箱是否注册，无论邮箱是否存在，页面都应显示相同的受理结果。

用户可以在登录页点击“忘记密码”，进入找回密码页面，填写注册时绑定的学生邮箱并发送验证码，再填写邮件中的6位验证码、新密码和确认新密码。发送请求被受理后，页面显示60秒重新发送倒计时；验证码是否可用和发送频率仍由服务端最终判断。

- 新密码必须满足与注册相同的密码规则。
- 密码重置验证码只能成功使用一次，注册验证码不能用于改密。
- 重置成功后，所有设备上的旧登录凭证都会失效，需要使用新密码重新登录。
- 页面会清理当前浏览器的旧登录状态，显示重置成功并提供“前往登录”入口，不会自动登录。其他设备在下次请求时确认旧登录已失效。
- 页面显示输入错误或服务端错误；提交完成或离开页面时清除新密码，不保存账号密码。
- 重置密码不会恢复停用账号，也不会自动解除尚未结束的登录失败临时锁定。
- 如果验证码已经通过，但保存时遇到临时故障或账号状态变化，需要重新获取验证码后重试。

### 用户名和密码登录

用户可以从顶部导航或首页进入登录页，填写注册时的用户名和密码。登录成功后返回首页，导航显示当前用户名。

- 登录使用用户名，不使用校园邮箱；密码中的空格会保留，不能随意增减。
- 登录后默认保留登录状态，无需勾选“记住我”。关闭页面或浏览器后，在同一浏览器、同一网站地址再次访问时会自动向服务端确认登录状态。当前有效期为7天，访问网站不会延长有效期，到期后需要重新登录。
- 浏览器只保存登录凭证，不保存密码；浏览器禁止保存数据、使用隐私模式或清理网站数据后，可能需要重新登录。公共电脑使用完应主动退出。
- 同一浏览器的多个标签页共享当前登录；更换账号或退出时会同步到其他标签页。不同设备或浏览器仍有各自的独立会话，退出当前会话不会退出其他设备。
- 用户名不存在、密码错误或账号不可用时，显示相同的登录失败提示。
- 默认15分钟内累计输错5次会临时限制该账号登录，锁定15分钟后可以重试。
- 登录服务暂时不可用时不会放行请求；临时故障保留本地凭证，方便恢复后重试。

### 退出当前登录

已登录用户可以点击顶部导航的“退出”。服务端确认退出后，当前会话立即失效，即使此前的登录凭证尚未自然过期也不能继续使用。

如果服务端暂时无法完成退出，页面会显示失败提示并保留登录状态，用户可以重试。若当前凭证已经失效，页面会清除本地登录状态。

成功退出后，同一浏览器的其他标签页同步退出，再次打开网站也不会恢复本次登录。

### 更新后自动检查并发布

开发者将更新推送到 develop 后，系统检查前后端，全部通过后由服务器主动下载已检查的新版本并更新。检查失败会保留线上版本，发布后的启动检查失败会尝试恢复上一版程序。自动更新无需对 GitHub 开放服务器的 SSH 访问。

项目使用独立仓库，develop 为默认分支。首次自动检查和服务器发布已成功，可在 `http://8.137.98.235` 使用网站，并在新仓库的 Actions 页面查看每次检查与发布结果。操作说明见[自动部署文档](deployment.md)。

## 正在开发

### 管理员回收站与餐厅治理扩展

用户已确认未登录可以浏览餐厅，新增餐厅和发布评价必须登录，并批准[首批表结构方案](architecture/restaurant-schema.md)。建表脚本只初始化13类，不自动灌入店铺或评价；本地开发库已升级并手动加入联调数据，线上数据库未在本轮升级。

已实现读取分类、搜索筛选餐厅、排序分页和查看详情的后端接口。未知人均和位置会保留为空，停业仍可查看，删除记录不会出现在公开查询中；没有评价时保持待评级，不会被算成推荐或踩雷。

本轮补齐新增、编辑、删除、读取管理资料及管理员恢复的接口。新增必须登录并确认真实位置，创建者由当前账号确定；普通用户只能编辑和删除自己的店，管理员可纠错和恢复。保存会检查名称、地址、人均及标签，重复标签保留第一次出现的位置。按用户决定，餐厅保存不要求版本号，最后成功保存的整份资料生效；旧页面再次保存也会覆盖之前的内容。资料和标签仍一起保存，失败一起回滚，不能出现只改一半的状态。删除会隐藏店铺并保留历史标签，管理员恢复后可重新阅读，停业状态不会因恢复改变。

上述接口及新增/编辑/删除页面已在本仓库完成；线上能力以实际部署版本为准。回收站列表与页面、同名同址提示、写入频率限制和审计等扩展仍待后续。空库显示空目录，不自动以候选资料填充；25家模拟店仅由开发工具手动写入。历史未知归属店不允许普通用户认领；评价、图片和地图仍未实现。

当前支持各次登录分别保持会话和退出当前会话；查看设备列表、主动退出其他设备的管理页面及接口尚未完成。

### 认证增强与部署完善

基础认证已验收通过；刷新令牌与自动续期、安全审计写入、域名及 HTTPS 等能力仍需独立排期，不属于当前已完成范围。

## 尚未实现的主要业务

以下功能属于产品目标，目前还不能在 V2 中正式使用：

- 美食地图与回收站页面；餐厅目录、详情、新增、编辑和删除已在本地接入接口。
- 查看真实聚合评分和其他用户发布的评价。
- 发布、修改和删除自己的评价。
- 在评价下回复，查看杯型排行榜和用户贡献榜。
- 收藏餐厅或建立个人美食清单。
- 上传评价照片并在餐厅详情展示。
- 管理员审核内容和处理违规信息。
- 回收站页面、评价/图片恢复、导入收集表、导出与恢复业务数据；餐厅按ID恢复的后端接口已实现，尚未发布。
