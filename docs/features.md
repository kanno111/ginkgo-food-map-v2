# Ginkgo 美食地图功能说明

核对日期：2026-10-30。本文说明当前能做什么、如何使用以及尚未接通的能力。产品规则与验收条件见[需求](requirements.md)，已实现接口见[接口文档](api.md)。线上可用版本以实际发布为准；本地独立预览不代表后端能力已上线。

提交点评时，正文不足5字、未选择餐厅或网络失败的原因会显示在提交按钮旁，无需滚动寻找。等待加载或发布时也会显示状态；发布中不能取消，失败后保留草稿供重试。

## 当前已经可以使用

本地开发可在被Git忽略的backend/config/application-local.yml填写OSS的access-key-id和access-key-secret，两个字段需同时填写；都留空时使用环境变量。本机凭证已通过真实OSS独立验收，开发库已升级V7，前后端已重启，可登录进行页面联调。

图片上传与带图发布代码已接通：选图后先压缩并本地预览，同时上传；最多五张，全部上传成功后才能提交。失败可重试或移除；取消立即尝试清理未绑定图片，异常退出由过期回收兜底。发布成功后按选择顺序绑定，关闭成功回执不会误删。正式图片访问校验点评与餐厅；详情页已接真实点评列表和照片，历史按需展开已接通，独立照片墙仍待实现。开发OSS已通过真实上传、读取和删除的独立验收，开发库已升级V7，新后端与前端已启动，可进行页面联调。

### 浏览餐厅目录与详情

首页以找店为主：搜索店名、地址、分类或标签，选择快捷分类、更多筛选及杯型，排序并分页查看餐厅。目录、分类、详情来自真实后端，失败可重试，没有结果时显示空态。当前页面尚未读取新的评价统计，显示待评级；评分维度排序暂不能体现评分差异，推荐/踩雷筛选不会凭空产生评分。

首页使用上图下文卡片：宽屏三列、中屏两列、手机单列，保留电脑和手机底部导航。搜索与快捷分类紧凑排列，低频条件收纳到“更多筛选”，随机推荐为浅黄色横条。卡片读取当前页各店的点评第一页，展示其中一张实际配图及接口返回的总评价数；模拟配图明确标注非本店实拍。没有图片或读取失败仍展示餐厅和统一占位，尚未获得评分的店继续显示待评级；这不代表评分统计已接通。

点击餐厅可直接打开或刷新详情链接，查看资料、地址、标签与位置状态，复制地址或分享；复制失败时可手动复制。详情无宣传大封面，缺少点评照片时显示占位，不冒用示例餐图。

部分本地店铺带“联调模拟”标签，仅供测试，经营、地址和消费资料未经核实；未知位置不会填入校园坐标，也不伪造距离。模拟店资料没有可核实的原站评分和原站账号归属。

本地现已准备“模拟食客_小林_1030”和“模拟食客_小周_1030”两个普通测试账号，各有16条点评，覆盖10家模拟餐厅（餐厅20各有7条记录，其中6条为历史），每条附1张美食示意照片。正文明确标注联调模拟并注明图片来源，不代表实际到店体验；登录信息保存在本机联调资料目录，不发布为公共账号。详情页可直接查看这些样例，餐厅汇总评分仍待接入。

### 今天吃什么

点击“帮我选一家”，按当前搜索、分类及杯型条件随机选店，可追加预算限制并换一家。手机从底部展开、电脑居中展示；候选覆盖全部符合条件的餐厅，排除标注停业的店，不自动放宽条件。未知价格不当作满足预算。

### 新增、编辑和删除餐厅

搜索结果底部、空态及写评选店处有“没找到？添加餐厅”入口。未登录时先登录再回新增页。可以填写名称、分类、人均、地址、标签、经营状态，并手动确认位置；地图搜索和选点尚未接通。

人均支持未知、填报金额和估值。保存检查必填信息、金额、坐标及标签；失败保留输入，离开未保存页面会提醒。切换账号后不能沿用上一账号草稿提交。

只有创建者或管理员能编辑、删除相应餐厅，权限由服务端核验；普通用户不能认领未知归属的模拟店。编辑保存整份资料，最后成功保存的内容生效。删除需再次确认，删除后公开列表和详情隐藏；停业仍可浏览。管理员按ID恢复接口已存在，回收站页面尚未完成。

### 查看杯型评分说明

首页、导航及详情可进入评分说明，查看四维、杯型和待评级含义。杯型保留原颜色和标语；展示舍入不改变实际判档。具体计分规则统一见[需求的评分章节](requirements.md#score-01评分计算与杯型原版迁移p1正确性-p0)。

### 注册、登录、找回密码和退出

- 注册使用允许的校园邮箱域名，当前默认为`@std.uestc.edu.cn`。验证码6位、5分钟有效，同邮箱60秒内不能重发，并有发送次数和错误次数限制；成功使用后失效。
- 用户名为3–32个文字、数字或下划线，密码至少8个字符并含文字及数字。用户名、邮箱不可重复，注册成功后需自行登录，不预建账号或管理员。
- 登录使用用户名和密码。手机可从“我的”进入账号页，桌面保留直接入口；未登录点击需要身份的操作会引导登录并安全返回。
- 默认保留登录7天，不自动续期；不保存密码。同浏览器多标签页同步账号和退出，不同设备独立保持会话。默认15分钟内累计输错5次会限制登录15分钟。
- 找回密码使用独立验证码，受理提示不泄露邮箱是否已注册。重置后所有旧会话失效，需要重新登录；不会恢复停用账号或解除未结束的登录限制。
- 退出仅撤销当前会话；失败会提示并允许重试，不提前显示成功。临时服务故障保留凭证供恢复后重试。

### 更新后自动检查并发布

推送develop后先检查前后端，检查通过再部署。检查失败保留原线上版本；新版本启动检查失败会尝试恢复上一版程序。操作及数据库回滚边界见[部署说明](operations/deployment.md)。

## 点评发布与阅读

### 写点评与查看点评

首页和详情写评支持文本及最多五张照片：登录后填写评分、推荐和正文，照片先完成上传再提交。成功显示点评编号；同内容失败重试保留文件ID和UUID。发布中冻结表单，登录失效时正文锁定可复制。暂不提供餐厅预测分数。

详情具备评分、点评卡片和图片等展示组件。详情页已接入公开点评列表：不登录也能按人翻页，每人显示最新点评，附历史条数和按选择顺序排列的照片，点击可看大图。列表分别显示评价人数和点评总条数；失败可重试，切换餐厅不混入旧请求结果。发布成功保留编号回执，点击完成或关闭回执后刷新第一页。历史点评已支持按需展开，每次5条，可加载更多，保留原记录的评分、时间、正文和照片；删评和独立照片墙仍未开放。餐厅汇总评分、推荐率和四维统计按用户要求暂缓，页面明确提示待接入。

点评默认只展示作者、评分、正文、照片及一行“回复 / 查看回复 / 历史点评”操作，移除重复的“评价依据”折叠块。点击“查看回复”才读取列表，每次10条，按时间从早到晚展示；点击“回复”才显示编辑框，支持1–200字纯文本、回车发送与Shift+回车换行，输入法选字不误发。同一时间只显示一个编辑框，取消或切换点评保留各自草稿。历史点评在桌面右侧面板、手机底部面板中按需读取，关闭后返回原位置，重开保留已读内容与草稿，历史照片和回复仍属于原点评。

游客可读，点击回复引导登录。发送失败保留文字和同次请求编号；成功后关闭编辑框、只刷新当前点评的回复区，保留历史面板和点评分页。发送成功但读取失败会单独提示，可只重试读取。切换账号会清空旧账号草稿，回复不影响评分。当前接口未提供回复总数，因此入口不显示未经读取的数量。

### 多次点评展示预览

首页页尾“多次点评展示预览”或`/previews/review-history`可以查看明确标注的示例。小王同店两次点评归在一张主卡内，最新点评在上方，旧点评默认收起，展开保留原回复；小李独立成卡。

初始示例为3条点评、2人、综合7.50分。可以切换当前计分记录，演示删除最新点评后的8.50分及重置。所有操作只影响预览页面，不写入数据库。正式规则见需求，后端实现见[计划](plans/review-backend.md)。
