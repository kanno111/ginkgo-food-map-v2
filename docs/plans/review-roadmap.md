## 实施顺序

A步和提前实施的图片上传/绑定/访问已完成，接下来推进B步，让已发布的内容可以被真实读取，再完成C步历史与预测。按以下最小步骤分别实现、验证和审核：

| 顺序 | 交付 | 验收边界 |
| --- | --- | --- |
| B1 点评读取后端（已实现） | 公开GET按作者分页，每人一张最新主卡；返回作者公开信息、四维、推荐、正文、时间、历史条数及有序图片引用 | 同人多评只占一组；按账号ID独立；计数/本页同一快照；已删餐厅404；五图顺序正确；批量查询作者/图片 |
| B2 餐厅真实统计（后端已实现） | 列表/详情及管理回执读取真实均分、推荐率、杯型、评价人数和点评条数；同步后端筛选排序，保留首次发评惰性初始化 | 3条/2人样例为7.50分、50%推荐；无评价为空、有评价0分有效；筛选/排序在分页前完成；缺零统计行只读兼容 |
| B3 页面接入与发布刷新（点评部分已接入） | 正式点评列表按作者分页，展示真实照片；关闭发布回执后回第一页刷新，餐厅统计区及人数/刷新已接通 | 真实浏览器读取/照片、失败重试、切店不串数据、回执保留已验证；正向持久化发布与跨设备验收仍待完成 |
| C1 历史展开（已完成） | 点击后按游标加载该作者历史，检测当前代表是否变化 | 不全量内嵌历史，不重复展示当前点评；保留原点评的照片及后续回复归属 |
| C2 本人上下文与预测 | 登录后读取本人当前计分及统计快照，按替换旧分计算预测 | 首次加人数，再评人数不变；并发下标明估算；缺少上下文时不展示推测值 |
| D 回复与删除 | 单层回复及本人删除已接通，V8独立回执防重放、作者授权、代表回退及图片清理 | 回复留在原点评；删除历史/代表/最后一条计分正确；旧UUID不把已删点评重新发布 |
| E 照片墙、榜单与全站联动 | 独立照片墙读取、后续推荐榜、贡献榜及全站统计/分享联动 | 照片墙不把当前点评页当全店照片；榜单仅含公开餐厅，贡献分组审核后实施 |

B1先交付读取接口及隔离数据库验证，不捆绑历史、预测或删除。B1–B3完成后才验收发布到阅读的基本页面闭环；C步补齐同人历史体验。各步细节与拟定协议见[后端计划](review-backend.md)。统计重建服务、分组查询EXPLAIN及并发/故障证据随相关阶段补齐，不能用以往测试结果替代本轮验证。

评价编辑、软删除/恢复、点赞、多级回复、收藏和独立个人内容管理页不纳入当前评价阶段。食堂窗口暂不推进。地图、数据导入导出、备份恢复、离线同步及PWA仍在整站需求清单中，分别排期，不混入文本发布的验收。
