## 3. 按原站执行的行为与必要适配

不再把已核实的原站行为替换成新产品限制：

1. **直接发布、公开阅读**：不新增发布前审核或待批准状态。发布须登录，沿用V2认证；服务端成功后其他用户可读。
2. **同一用户同店可多评**：保留不同用餐经历，不加作者/餐厅唯一约束。同次网络重放防重，不能禁止下一次真实评价。
3. **停业店允许评价**：原表单可选且提交未禁止，暂不增加“停业禁止新评”。停业与删除分离。
4. **有评价不自动禁止创建者删店**：沿用已有创建者/管理员权限，删除前提示关联评价并确认。评价不物理销毁，恢复父店不复活已独立删除评价。
5. **不增加每日次数/发布冷却等产品门槛**：原站未发现对应规则。按钮防重、同次幂等及故障处理仍需具备。
6. **独立“我的评价”页、评价编辑、收藏、举报、点赞暂不新增**：原站未发现完整入口。自己的评价先在原有详情内管理。

### 3.1 登录身份（用户最新指示优先）

评价、回复、上传照片均须登录；未登录点击写评价自动跳转登录页，登录成功返回经过校验的站内原页面继续填写，不自动发布；回复同样引导登录，后端独立拒绝未认证写入。显示账号用户名，撤回匿名社员、自填昵称、记忆昵称和餐厅新增created_nickname的方案。

评价/回复作者及文件上传者ID均非空，新表移除source_type，不预留未知历史作者例外。原站昵称榜分组不再直接照搬；建议按账号汇总，但榜单分组方案待单独审核，不视为已经批准。

### 3.2 照片口径

实测同时选3个文件只保留2张，支持移除。详情空态仍写“最多3张”，与实际表单/代码不符，按实际2张实现并统一文案。

保留点击/拖拽、缩略预览、移除及自动压缩。原代码最长边1200px、目标200KB，最终允许不超过300KB；据此设计压缩和独立服务端校验。原同步过大时只传文字是缺陷，不作为复刻目标：失败明确反馈、可重试或由用户移除后提交，不能无声丢图。

## 4. 评分、详情及榜单

- 四维全部必填，0分有效；7.0只是新表单初始值，不生成历史评价或预设餐厅评分。
- 单条总分四维平均，十进制HALF_UP保留2位；8、8、8、7.5得7.88。餐厅综合分是全部有效评价的单条总分再平均。
- 四维均分分别算，推荐率为推荐条数/评价数；无评价为null、0条、none，真实0分为小杯。
- 杯型以未舍入综合分判定，阈值8.6/7.4/6.2/5.0；8.55显示8.6仍为超大杯。保留原SVG、颜色、标语和显示精度。
- 详情包括雷达图、四维条、综合分/推荐率/评价数、最新评价、照片墙、大图、回复；分享摘要使用正式评分，保留已有直达详情链接。
- 杯型榜每档最多3家、含待评级组，同组分数降序、同分名称排序。不增加最低评价数、加权分或商业置顶，也不自动排除停业店。
- 榜单复用公开有效集合，已删除餐厅不能借榜单进入；原代码个别未复用公开过滤的缺口按V2既有软删除边界修正。
- 首页统计、卡片、筛选/排序、详情和榜单共用真实聚合。全站平均沿用全部有效评价总分的平均，不改为各店平均分的平均。

## 5. 技术结构

后续新增迁移，保持V1/V2/V3，不自动复制原站真实数据。

R1已整理[评价表结构草案](../architecture/review-schema.md)供用户先审核：建议新增5张表，不再增加餐厅展示昵称字段；字段、索引、幂等、父子可见性、评分事务和文件清理规则均在草案中。用户已要求开始表迁移，V4及结构测试已新增并验证，本地开发库已升级；具体上传/接口协议继续设计，尚无评价API。

| 数据 | 模块 | 作用 |
| --- | --- | --- |
| 评价记录 | review | 餐厅、真实账号、四维、推荐、正文、正式总分、时间及请求标识，删除采用物理删除 |
| 评价照片关联 | review | 文件ID与0–1有序位置，最多2张，不接收任意外部URL代替上传 |
| 回复记录 | review | 所属评价、真实账号、1–200字正文、时间，单层 |
| 媒体文件 | file | 上传者、状态、真实类型/大小/尺寸、持久位置及绑定生命周期 |
| 餐厅评分读模型 | restaurant | 评价/推荐数、四维累计分和单条总分累计值，支持全局筛选排序 |
| 贡献/全站统计 | 各模块公开服务协作 | 汇总原版昵称贡献和全站指标，不跨模块访问Mapper |

用户已选择阿里云OSS存储图片，数据库记录Bucket、Object Key和归属/绑定状态，不保存图片本体或签名URL。建议私有Bucket及后端校验后读取，上传/访问协议仍在R1评审；不创建云资源或读取凭证。

评价发布/直接删除与评分同事务完成，经restaurant公开服务锁父餐厅并校验状态，再操作review自有表、重算统计并更新restaurant读模型。媒体经file公开服务，身份经security公开服务；餐厅Mapper只关联自己的统计表，在全局筛选排序后分页。餐厅不重新引入版本号。

餐厅/评价删除同时约束子回复和照片公开读取；恢复不复活独立删除的内容。草稿照片仅上传者可用，提交失败可重试；删除评价解除关联并持久标记待清理，失败可重试，不保留恢复。不能用永久公开文件地址绕过父内容状态。

同次请求标识和数据库唯一约束避免重放重复计分，不合并不同经历。账号切换锁住原草稿，昵称不用于授权。具体规划接口只在本方案讨论，正式实现后再写入[接口文档](../api.md)。

1. 首页与详情均可写评，详情默认当前店，可切到全站其他店/停业店；四维默认7、推荐默认选中；未登录写评跳转登录。

9. 8.599/8.600等阈值、0分/10分、7.875→7.88、显示8.6但超大杯等边界通过。
10. 杯型每档前三及待评级、贡献前10/奖牌/我的排名、已确认的贡献分组、删除重算通过。
