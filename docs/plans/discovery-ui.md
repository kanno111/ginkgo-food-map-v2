# 学生找店前端方案（2026-10-29）

本方案按用户最新讨论替代“完全照搬原站界面”的约束；保留已确认账号权限、杯型与标语、原封面素材及既有业务规则。先固定找店流程，额外治理功能待内测。

- 首页以餐厅为主体，无独立点评流；搜索、分类、筛选、目录与“今天吃什么”共同服务选店。手机使用紧凑顶部与底部五入口：首页、地图、写点评、消息、我的；电脑使用宽屏顶部筛选与双列列表。餐厅详情集中展示资料、评分、学生点评与回复，无顶部宣传大封面。
- 随机推荐先给结果，复用当前目录条件，并可限制人均预算；全量候选查询后抽取，不能只从当前页抽取。显示候选范围与理由，换一家优先排除当前结果，不自动放宽条件；未知价格不能声称符合预算。取消或条件改变后旧请求不得覆盖。
- 商户类型（食堂档口/独立门店）与用餐方式（堂食/外卖）属于不同维度，未来按正式字段筛选。现有接口尚无这些字段，不把名称或标签猜测为正式服务能力，不放可操作但无效果的筛选。
- 首页缩略图来自该店最新带图点评的第一张图，标注“同学上传”；无图显示统一餐具占位。详情照片归属各自作者和点评，不另外要求商家或某个学生上传封面。图片接口未接通时使用真实无图状态，不使用示意图照片冒充真实数据。
- 可信价值通过可确认的信息呈现：评价数、附图数量、发布时间和可展开的依据说明；不把图片当作核实到店，不使用任意可信度百分比或绿勾认证。
- 添加餐厅保留为次级入口：目录搜索结果与写评选店处提供“没找到？添加餐厅”，沿用现有登录和确认位置要求。未来顺序为站内已有店→高德地点搜索→仍无结果手动补录；导航与地点数据接入分开处理，当前不假装已接入高德。
- 地图、消息、账号导航提供明确的能力状态；不生成假通知、假地图或假点评。评价、照片、消息、高德的正式接口和持久化仍单独实现，不以完成外观宣称已接通。

验收：320px、390px手机与桌面无横向溢出；真实目录搜索/分页/详情和登录流程保留；随机推荐与当前筛选一致，故障、空态、未知值明确；原有未提交成果保留，不提交、推送、部署或修改迁移。

## 当前实现与验收边界

- 新布局取代旧首页宣传首屏；白底、暖橙搜索、图形分类、条件入口、随机横幅和带缩略图占位的店铺列表已实现。杯型本身继续使用既有颜色。
- 手机随机推荐从底部展开，电脑居中展示；预算、换店、查看详情、关闭与失败重试已实现。详情手机端先呈现评分与点评，复制和写评操作固定在底部，桌面附地址资料侧栏。
- 真实目录接口提供搜索、分类、排序、分页和详情；尚无评价照片、堂食/外卖、商户类型正式字段，因此示意图中的实拍图和服务标签不伪造。
- 验证使用本地真实餐厅接口和Edge；故障重试单独拦截为503。不会发布评价、创建餐厅或把测试夹具写入数据库。页面完成不代表高德、消息、评价或OSS接通。
